# PRD — Demo Redesign Anugrah Laundry Cimahi

## 1. Project Overview

### Project Name

Anugrah Laundry Cimahi — Website Redesign Demo

### Project Type

Website redesign concept / sales demo

### Brand

Anugrah Laundry Cimahi - Antar Jemput

### Purpose

Membuat demo website yang menunjukkan bagaimana informasi Anugrah Laundry dapat disusun lebih sederhana sehingga pelanggan dapat:

1. Mengetahui layanan yang tersedia.
2. Melihat harga dengan cepat.
3. Memahami layanan antar-jemput.
4. Menemukan kontak WhatsApp.
5. Melakukan pemesanan dengan lebih mudah.

Website ini adalah **demo redesign untuk presentasi kepada calon klien**, bukan klaim sebagai website resmi yang menggantikan website milik Anugrah Laundry.

# 3. Important Data Rules

Data berikut berasal dari informasi publik yang ditemukan dan harus dianggap sebagai data yang perlu dikonfirmasi sebelum digunakan sebagai informasi resmi:

- Harga
- Jam operasional
- Detail cakupan antar-jemput
- Ketentuan express/kilat
- Detail layanan tambahan

Jangan membuat informasi bisnis baru.

Jangan membuat:

- Harga baru
- Promo palsu
- Testimoni palsu
- Klaim kualitas yang tidak tersedia
- Sertifikasi palsu
- Jumlah pelanggan palsu
- Garansi palsu

Jika harga digunakan dalam demo, tampilkan sebagai data demo yang perlu dikonfirmasi sebelum website dipublikasikan.

# 4. Current Problem / Opportunity

Website demo tidak dibuat karena bisnis tidak memiliki website.

Bisnis sudah memiliki digital presence.

Tujuan redesign adalah menunjukkan bahwa informasi bisnis dapat dibuat lebih sederhana dan fokus terhadap kebutuhan pelanggan.

Opportunity utama:

- Informasi penting dapat diprioritaskan.
- Harga dapat ditemukan lebih cepat.
- Layanan antar-jemput dapat dibuat lebih terlihat.
- WhatsApp dapat menjadi CTA utama.
- Pengalaman pengguna mobile dapat dibuat lebih sederhana.
- Pelanggan tidak perlu mencari terlalu banyak informasi sebelum menghubungi bisnis.

# 5. Target Users

## Primary User

Pelanggan laundry di Cimahi.

Karakteristik:

- Menggunakan smartphone.
- Ingin mengetahui harga dengan cepat.
- Ingin mengetahui layanan yang tersedia.
- Ingin mengetahui apakah laundry dapat dijemput/diantar.
- Lebih memilih komunikasi cepat melalui WhatsApp.
- Tidak ingin membaca informasi terlalu panjang.

## Secondary User

Pemilik / admin Anugrah Laundry.

Kebutuhan:

- Website mudah dipahami.
- Informasi bisnis mudah diperbarui.
- CTA WhatsApp jelas.
- Website membantu calon pelanggan sebelum menghubungi admin.

# 17. UX Requirements

## Primary UX Goal

Reduce the number of steps needed to:

- Find price
- Understand service
- Contact business

## Mobile First

Mobile is the primary design target.

Minimum considerations:

- Large touch targets.
- Readable typography.
- Sticky WhatsApp CTA.
- No horizontal scrolling.
- Price table converted into cards or horizontally scrollable component if necessary.
- Short paragraphs.
- Clear section hierarchy.

## CTA

WhatsApp should appear in:

1. Navbar
2. Hero
3. Antar-jemput section
4. Contact section
5. Mobile sticky CTA

Do not make the page feel spammy.

---

# 18. Visual Direction

Style:

- Modern
- Clean
- Trustworthy
- Friendly
- Local business
- Professional
- Simple

Avoid:

- Overly futuristic UI
- Excessive gradients
- Excessive animations
- Glassmorphism everywhere
- Excessive shadows
- Generic SaaS appearance
- Excessive decorative elements

The design should feel appropriate for a real Indonesian laundry business.

---

# 19. Performance

Requirements:

- Fast initial load.
- Optimized images.
- Lazy-load non-critical images.
- Avoid unnecessary libraries.
- Avoid excessive animation.
- Mobile performance must be prioritized.

---

# 20. Accessibility

Requirements:

- Good color contrast.
- Semantic HTML.
- Keyboard navigation.
- Alt text for meaningful images.
- Visible focus states.
- Buttons must have clear labels.
- Do not rely only on color to communicate information.

---

# 21. SEO

Basic SEO:

Title:
"Anugrah Laundry Cimahi - Laundry & Antar Jemput"

Description:
"Layanan Cuci + Setrika, Setrika Saja, Cuci Kering Lipat, dan antar-jemput untuk area Cimahi."

Use:

- Semantic headings
- Local business information
- Proper metadata
- Open Graph metadata

Do not create fake structured data or unverifiable claims.

---

# 22. Sales Demo Requirements

The website must visually demonstrate improvements over a more information-heavy website.

Key comparison:

CURRENT:
Information → multiple sections → user searches

DEMO:
Service → Price → Pickup → WhatsApp

The demo should make this difference obvious without explicitly criticizing the existing website.

# 23. Acceptance Criteria

The project is complete when:

- [ ] Homepage is fully responsive.
- [ ] Mobile layout is prioritized.
- [ ] Hero immediately explains the business.
- [ ] Services are easy to understand.
- [ ] Prices are easy to find.
- [ ] Pickup/delivery is clearly presented.
- [ ] WhatsApp CTA is prominent.
- [ ] Address is visible.
- [ ] Social media links are included where appropriate.
- [ ] No fake business information is added.
- [ ] Demo data that requires confirmation is clearly marked.

- [ ] Page loads quickly.
